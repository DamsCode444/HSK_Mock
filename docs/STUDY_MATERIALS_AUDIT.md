## Source anomalies handled

1. All nine files named `.png` contain AVIF bytes (`ftypavif`). Their dimensions
   are valid portrait cover dimensions, but extension-based serving would use
   the wrong MIME type. The importer generates genuine 720×960 WebP covers
   and 26 separate book thumbnails from their first pages, so A/B volumes and
   workbooks show their own cover.
2. Six workbook audio folders contain one consolidated recording beyond the
   book's canonical lessons: L1=16, L2=16, L3=21, L4B=21, L5B=37, and L6B=41.
   These are labeled “Final review audio,” not ordinary lessons.
3. `HSK-4B-Workbook.pdf` opens and has 120 pages, but its source has five
   recoverable malformed-object/xref warnings. Browser PDF rendering should be
   rechecked if this source file is replaced or normalized.
4. All 26 PDFs open, are unencrypted, and have page counts. All 1,215 logical
   MP3s have valid MPEG Layer III headers. The three ZIP CRC checks pass, and
   their member paths are safe.
5. There are no zero-byte files, unsupported hidden files, case-fold path
   collisions, or byte-identical duplicate groups.

## Import and storage behavior

Run from the project root:

```powershell
backend\.venv\Scripts\python.exe scripts\import_hsk_materials.py
```

The generated manifest is `storage/materials/manifest.json`. The importer:

- assigns deterministic semantic IDs by edition, level, volume, book, lesson,
  and track;
- records file size, SHA-256, page count, approximate CBR duration, bitrate,
  and sample rate;
- leaves all source files unchanged and serves loose HSK 2.0 files in place;
- safely extracts the three ZIP-contained HSK 3.0 audio sets to deterministic
  private paths (about 169 MiB total including covers/manifest);
- verifies ZIP track checksums on reimport, including same-size replacements;
- retains earlier extracted tracks when a replacement needs a new file, so a
  failed import does not overwrite audio used by the previous manifest;
- reuses unchanged files and fails explicitly if any source file is unmapped;
- rejects ZIP traversal, links, unsupported extensions, path collisions,
  excessive member counts/expanded size, and suspicious compression ratios;
- never copies the 2.8 GB loose audio library or stages giant bundle ZIPs.

Audio-only and book-plus-audio packs are streamed as ZIP_STORED archives from
the existing assets. HSK 3.0 audio-only downloads reuse their supplied ZIPs.

## Delivery and access model

- `GET /api/materials/catalog` and collection metadata are public.
- Corrected covers are public and cacheable.
- Reading, listening, and every download require a verified Clerk session.
- The API grants a short-lived URL scoped to one user, resource, and
  inline/attachment purpose. Media requests re-check that the local account is
  present and active.
- PDFs and MP3s are delivered with byte-range support. Native `<iframe>` and
  `<audio>` elements therefore seek without loading the complete file.
- Source/storage paths and absolute Windows paths are never returned to the
  browser. Every resolved path is confined to an explicitly configured root.
- The legacy `/media` mount blocks the private materials directory, including
  encoded paths and Windows case variants. Configure any production static
  server to preserve this exclusion rather than serving all of `storage/`.
- Very large downloads display their estimated size before starting.

## Rights checkpoint

No README, license, or redistribution permission is present in the supplied
folder. Several PDFs contain publisher/title/ISBN metadata associated with
commercial course books. Possessing these local files does not itself establish
permission to host, stream, or offer them for download.

Before a public deployment, obtain and document the necessary rights for every
book, cover, and audio set. Until then, keep the application within an
authorized private audience. Authentication and expiring URLs reduce accidental
exposure but do not replace copyright permission.
